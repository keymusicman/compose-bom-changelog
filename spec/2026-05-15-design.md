# Compose BOM Changelog — Design Document

Date: 2026-05-15

## Problem

When upgrading the Jetpack Compose BOM, there is no single place to see what changed.
The official BOM mapping page shows version numbers but no diffs. AndroidX release notes
are scattered across individual library pages. This tool aggregates everything into one
shareable page.

---

## Product Requirements

- Select two BOM versions to compare (FROM / TO)
- Aggregate release notes for every library that changed
- Filter which libraries are shown via a checkbox popup
- Show libraries that have not changed (hidden by default, toggled on per user)
- "What's new" articles shown as callout cards when applicable for the compared range
- Comparison is shareable via URL query params
- Default comparison: latest BOM vs the one before it
- Fully responsive — works on mobile phones

---

## Architecture

### Approach: Static site + committed JSON + scheduled CI

```
compose-bom-changelog/
├── collector/
│   ├── collect.py          # scraper: BOM mapping + AndroidX release notes
│   └── requirements.txt    # httpx, beautifulsoup4, lxml
├── data/
│   ├── bom-data.json       # auto-generated by collector (committed to repo)
│   └── whats-new section   # hand-edited inside bom-data.json (see data spec)
├── site/                   # SvelteKit app
│   ├── src/
│   │   ├── routes/
│   │   │   └── +page.svelte
│   │   └── lib/
│   │       ├── diff.ts
│   │       └── types.ts
│   └── svelte.config.js    # adapter-static
├── spec/                   # design documents
└── .github/
    └── workflows/
        ├── collect.yml     # scheduled + manual → runs collector → commits JSON
        └── deploy.yml      # deploys site on push to main → GitHub Pages
```

### Data flow

1. GitHub Actions `collect.yml` runs on a weekly schedule (or manual trigger)
2. Python collector scrapes BOM mapping and AndroidX release notes → writes `data/bom-data.json`
3. Commit pushed to `main` triggers `deploy.yml`
4. SvelteKit build copies `bom-data.json` into `static/data/`, builds static site
5. Deployed to GitHub Pages with custom domain support

## Data

See [bom-data-structure.md](bom-data-structure.md) for the full JSON spec.

Summary:
- `bom_versions` — keyed by BOM version string; libraries grouped by Maven group ID
- `library_releases` — keyed by Maven group, then version; holds parsed release notes
- `whats_new` — keyed by BOM version string; array of articles per version; hand-edited

---

## Python Collector (`collector/collect.py`)

**Sources:**
- `developer.android.com/develop/ui/compose/bom/bom-mapping` — BOM → library group version map
- `developer.android.com/jetpack/androidx/releases/{library}` — release notes per version

**Behaviour:**
- Additive only: reads existing `bom-data.json`, adds new BOM versions and library release entries
- Never re-scrapes a library version that already exists in the file (data is immutable once published)
- Never touches the `whats_new` section
- Parses release notes into `new_features`, `bug_fixes`, `api_changes` sections
- Writes `last_updated` timestamp on every run

**GitHub Actions schedule:** weekly + `workflow_dispatch` for manual runs

## Site

### Tech stack

- **SvelteKit** with `@sveltejs/adapter-static`
- Deployed to **GitHub Pages**
- `bom-data.json` fetched at runtime from `/data/bom-data.json` (static asset)

### URL scheme

```
/?from=2026.04.00&to=2026.05.00
```

Both params are synced on every change. Landing with no params defaults to
latest BOM vs the one before it.

### Layout

```

├─────────────────────────────────────────────────────┤

│          │                           │              │
```

### Components

| Component | Responsibility |
|---|---|
| `BomSelector` | Two dropdowns (FROM / TO); reads and writes URL query params; triggers diff recompute on change |
| `LibraryFilter` | Button that opens a popover with a checkbox list of all libraries in the comparison; "Show unchanged" toggle at the bottom |
| `WhatsNewCard` | Callout card for a single "What's new" article; shown for every article whose BOM version falls within the compared range |
| `LibraryDiff` | Card for one changed library: version badge (`1.11.0 → 1.11.1`), link to release notes URL, expanded change sections |
| `ChangeSection` | Renders one of `new_features`, `bug_fixes`, or `api_changes` as a labelled bullet list; hidden when empty |

### Diff logic (`src/lib/diff.ts`)

Pure function — takes two BOM version strings and the full loaded data, returns:

```ts
type DiffResult = {
  changed: LibraryDiff[]   // libraries whose version changed, with release notes
  unchanged: string[]      // library group names with no version change
  whatsNew: Article[]      // all articles for BOM versions within the compared range
}
```

The result is derived entirely from `bom-data.json` — no network calls at diff time.
